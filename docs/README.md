# docs

코드와 함께 버전 관리되어야 하는 문서만 둔다. 설계 문서(개요·도메인·기능 명세·데이터 모델·주차별 계획 등)의 정본은 Notion `EZ › 프로젝트 › 공시 (gongsi)` 이며 여기에 복제하지 않는다.

| 폴더 | 내용 | 변경 규칙 |
| --- | --- | --- |
| `conventions/` | 협업 규약 — 커밋·브랜치·PR·코드 스타일 | PR 필수, 양쪽 승인 |
| `adr/` | 아키텍처 결정 기록 | PR 필수, 양쪽 승인. 확정된 ADR은 수정하지 않고 새 ADR로 대체 |
| `api/` | 제공 측 REST API 계약 (Swagger 보완) | 담당자 PR, 상대 리뷰 |
| `survey/` | 사전 조사 기록 — 실측값·관측 로그 | 담당자 직접 커밋 가능 |
| `runbook/` | 운영 절차 — 배포·데이터 이전·복구 | 담당자 PR |

## 문서 추가 규칙

- 새 종류의 문서가 필요하면 폴더를 하나 추가하고 이 표에 한 줄 보탠다. 예: `runbook/`(운영 절차), `db/`(마이그레이션 메모).
- 폴더마다 `README.md` 하나로 그 폴더의 목적과 파일 규칙을 적는다.
- 파일명은 소문자-하이픈. 날짜가 의미 있는 기록은 `YYYY-MM-DD-제목.md`.
- 한 문서는 한 가지 질문에만 답한다. 같은 내용을 두 곳에 쓰지 않는다.
