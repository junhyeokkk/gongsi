# 권역 (은행 · 저축은행)

권역이 무엇이고, 권역별로 데이터가 어떻게 들어오며, 어디에 어떻게 남기는지.
상품군별 필드 매핑은 [product-types/](product-types/README.md), 전체 설계는 [data-model.md](data-model.md).

## 권역이란

금감원 API 는 금융회사를 권역으로 묶고, 요청할 때 `topFinGrpNo` 로 권역 하나를 고른다.

| 코드 | 권역 | 수집 |
| --- | --- | --- |
| `020000` | 은행 | 함 |
| `030300` | 저축은행 | 함 |
| `030200` | 여신전문 | 미정 — 대출 상품만 있을 것으로 보여 1회 호출 후 결정 |
| `050000` | 보험 | 미정 |
| `060000` | 금융투자 | 미정 |

수집 권역 목록은 `FetchService.FIN_GRP_NOS` 다.

## 원문 어디에 권역이 있나

**레코드 안에는 없다.** baseList·optionList 어디에도 권역 필드가 없고, 어느 권역으로 요청했는지로만 갈린다.

- 수집: 권역 × 페이지마다 `raw_snapshot` 한 행. 키가 `(fetched_on, product_type, fin_grp_no, page_no)`
- 정규화: 페이지의 `fin_grp_no` 를 그 페이지 상품의 `product.fin_grp_no` 로 옮겨 적는다(V2)
- 금융회사 목록(`companySearch`)도 같은 권역으로 받아 `company.fin_grp_no` 에 둔다(V3, [company.md](company.md))
- 회사코드·회사명("○○저축은행")으로 추정하지 않는다 — 공식 규칙이 아니다

## 권역별 실측 (2026-10-30)

| 상품군 | 권역 | 페이지 | 상품 | 옵션 | 회사 | 상품당 옵션 |
| --- | --- | --- | --- | --- | --- | --- |
| 예금 DEP | 은행 | 1 | 40 | 164 | 18 | 4.1 |
| | 저축은행 | 4 | 396 | 2,654 | 79 | 6.7 |
| 적금 SAV | 은행 | 1 | 60 | 181 | 18 | 3.0 |
| | 저축은행 | 3 | 277 | 1,353 | 79 | 4.9 |
| 주담대 MORT | 은행 | 1 | 36 | 111 | 17 | 3.1 |
| | 저축은행 | 1 | 56 | 157 | 40 | 2.8 |
| 전세 RENT | 은행 | 1 | 41 | 80 | 17 | 2.0 |
| | 저축은행 | 1 | 8 | 16 | 8 | 2.0 |
| 신용 CRED | 은행 | 1 | 44 | 139 | 19 | 3.2 |
| | 저축은행 | 1 | 36 | 107 | 36 | 3.0 |
| **합계** | | **15** | **994** | **4,962** | | |

읽을 것
- 예·적금은 저축은행이 은행의 약 5~10배다. 회사 수가 4배 넘게 많고(79 vs 18), 가입기간을 잘게 나눠 상품당 옵션도 많다
- 대출은 은행 비중이 상대적으로 크다. 전세대출은 저축은행이 8곳 8상품뿐이다
- 하루 15페이지 = API 호출 15회. 저축은행 예·적금이 그중 7페이지를 차지한다

## 페이지는 어떻게 나뉘나

- 한 페이지 = **상품 최대 100개 + 그 상품들의 옵션 전부**. 저축은행 예금 396개는 100·100·100·96 으로 4페이지
- 회사 기준으로 끊지 않는다 — 한 페이지에 저축은행 19~23곳이 섞인다
- 옵션은 자기 상품과 같은 페이지에 온다(2026-10-28 예금 5페이지 모두 페이지 밖 base 를 가리키는 옵션 0건).
  API 가 보장한다는 문서는 없어서 정규화는 전 페이지를 다 읽은 뒤 고아를 판정한다
- `total_count`·`max_page_no` 는 권역 전체 기준으로 매 페이지 같은 값이 온다. 수집은 `max_page_no` 까지 돈다

## 권역과 키

- 같은 상품·같은 회사가 두 권역에 함께 나오는 경우 0건(2026-10-30) — 권역은 회사의 속성이다
- 그래서 `fin_grp_no` 는 자연키에 넣지 않는 일반 컬럼이다. 자연키는 `(inst_code, product_code, product_type)` 그대로
- 만약 겹치면 나중에 처리된 권역으로 덮인다. 그럴 일이 생기면 정규화 결과(상품 수 감소)로 드러난다

## 왜 남기나

- 조회: "은행만 / 저축은행만" 필터. 저축은행 금리가 대체로 높고 성격이 달라 따로 보려는 수요가 크다
- 알림: 구독 조건에 권역을 넣을 수 있다
- 확장: 여신전문·보험·금융투자를 추가하면 구분이 더 필요해진다
