원문 JSON 의 생김새 — base 와 option 두 목록

{
  "result": {
    "prdt_div": "D",
    "total_count": 37,
    "max_page_no": 1,
    "now_page_no": 1,
    "err_cd": "000",  // 000 아니면 실패
    "err_msg": "정상",
    "baseList": [ {          // 상품 1건 = 1행
      "dcls_month": "202610",
      "fin_co_no": "0010001",
      "fin_prdt_cd": "WR0001B",
      "kor_co_nm": "우리은행",
      "fin_prdt_nm": "WON플러스예금",
      "join_way": "인터넷,스마트폰",
      "max_limit": null,
      "dcls_end_day": null,
      "fin_co_subm_day": "202610281200", …
    } ],
    "optionList": [ {        // 금리 조건 1건 = 1행
      "fin_co_no": "0010001", "fin_prdt_cd": "WR0001B",
      "intr_rate_type": "S", "save_trm": "12",
      "intr_rate": 2.75, "intr_rate2": 2.85
    } ]
  }
}

읽는 법

  • baseList → 상품 테이블(product / credit_loan_product / company)
  • optionList → 옵션 테이블(product_option / credit_loan_option / company_area)
  • 옵션은 fin_co_no + fin_prdt_cd(신용은 + crdt_prdt_type)로 부모 base 를 찾는다
  • base 와 옵션이 서로 다른 페이지에 있을 수 있어 하루치 전 페이지를 모은 뒤 짝짓는다

값 정리 규칙 (JsonFields)

  • 필수 필드 누락·길이 초과 → MISSING_REQUIRED / TYPE_MISMATCH
  • 허용값 밖 코드(예: rate_type 이 S/M 이 아님) → UNKNOWN_ENUM
  • 부모 base 없는 옵션 → ORPHAN_OPTION
  • 날짜 yyyyMMdd, 99991231 은 null, 제출일시 yyyyMMddHHmm
  • 걸린 레코드는 버리지 않고 normalize_error 에 원문 위치와 함께 격리
예시 값은 형식 설명용 · survey/raw 에 실제 원문 픽스처

흐름 (전 상품군 한 트랜잭션, ADR-0003)

RateDiffService.detectChanges(targetDate) 1. RawSnapshotRepository.latestDatesBefore(type, date) — 권역별 직전 수집일 2. RawRateReader.read(parser, pages) ×2 — 오늘·직전 원문을 상품→옵션키→옵션으로 3. RateDiffCalculator.compare(prev, today, …) 4. checkNotPartial(…) — 급변이면 MassChangeException 5. ProductIdRepository.load(type) / loadCredit() — 자연키→id 6. RateHistoryRepository.insertAll(family, date, rows) 7. ChangeEventPublisher.publish(family, date, events)
  • 직전 원문이 없는 권역(첫 수집)은 비교하지 않음 [전부 NEW 폭주 방지]
  • 원문을 다시 읽는 이유: normalize 테이블은 "오늘 상태"만 있어 어제 값이 없다
