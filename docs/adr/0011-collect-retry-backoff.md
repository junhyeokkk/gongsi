# 0011 수집 실패 재시도 — 배치 메타 기반 판단, 10/30/60분 백오프

- 상태: 제안
- 날짜: 2026-11-17
- 담당: 준혁

## 문제

그날 받지 못한 원문은 다시 받을 수 없다(ADR-0001). 처음 스케줄은 KST 09:00·15:00 두 번(`0 0 9,15 * * *`)이라 둘 다 실패하면 그날이 빠지고, 실패해도 다음 시도까지 6시간을 기다렸다.
앱은 배포·장애로 재기동될 수 있다(ADR-0006). 재시도 상태를 어디에 둘지도 정해야 했다.

## 선택지

1. 09:00·15:00 두 번 실행을 유지한다
2. 짧은 주기로 깨어나되 실패 횟수를 메모리에 둔다
3. **짧은 주기로 깨어나 Spring Batch 메타 테이블에서 오늘 실행 기록을 읽어 판단한다**

## 결정

3번.

- 스케줄 `0 */10 9-17 * * *` (KST, 09:00~17:50 10분마다, `COLLECT_CRON` 으로 바꿀 수 있음)
- 깨어날 때마다 `JobExplorerAttemptHistory` 가 오늘 targetDate 실행 기록을 읽고 `RetryPolicy.decide` 가 정한다
  - 기록 없음 → 실행 / 완료 → 건너뜀 / 실행 중 → 건너뜀 / 마지막 실패가 `FAILED_NO_RETRY` → 건너뜀(ADR-0012)
  - 실패 n회 → 마지막 종료 + 10분 → 30분 → 60분(넷째부터 60분) 지나야 실행
- 재실행은 Spring Batch 재시작이라 실패한 Step 부터 이어서 돈다
- 오늘 마지막 스케줄을 넘기면 "오늘 자동 재시도 끝 - 수동 실행 필요" 를 알린다(ADR-0013)

## 근거

- 메모리 상태가 없어 재기동돼도 이어서 판단한다. 기록은 이미 배치 메타 테이블에 있다
- 판단을 순수 함수(`RetryPolicy.decide(List<CollectAttempt>, now)`)로 두어 시각·기록 조합을 단위 테스트로 덮는다

## 결과 · 트레이드오프

- 얻은 것: 하루 최대 약 9시간 동안 자동 재시도, 재기동에도 끊기지 않음
- 포기한 것: 판단이 메타 테이블 상태를 믿는다. 재기동으로 `STARTED` 에 남은 실행은 "실행 중" 으로 보여 재시도가 멈춘다 — ADR-0014 로 해결
- 17:50 이후 실패는 사람이 수동 실행해야 한다
