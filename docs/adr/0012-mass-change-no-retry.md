# 0012 급변 차단 — 재시도하지 않고 FAILED_NO_RETRY 로 멈춤

- 상태: 제안
- 날짜: 2026-11-17
- 담당: 준혁

## 문제

diffStep 은 상품군 상품이 하루에 max(5개, 10%) 넘게 사라지거나 생기면 원문 누락으로 보고 실패한다(ADR-0003, `RateDiffService`).
자동 재시도(ADR-0011)가 들어오면서 이 실패도 재시도할지 정해야 했다.

## 선택지

1. 다른 실패와 같이 백오프 재시도한다
2. **재시도하지 않는다 — 종료 코드를 `FAILED_NO_RETRY` 로 남기고 사람이 원문을 확인한다**

## 결정

2번.

- diffStep 이 `MassChangeException` 을 던지면 `NoRetryExitListener` 가 Step 종료 코드를 `FAILED_NO_RETRY` 로 바꾼다
- `RetryPolicy` 는 마지막 실패가 `FAILED_NO_RETRY` 면 그날 다시 띄우지 않는다
- 슬랙으로 "재시도 안 함 - 원문 확인 필요" 를 보낸다(ADR-0013)

## 근거

- diffStep 은 이미 저장된 raw_snapshot 으로만 비교한다. 같은 원문으로 다시 돌려도 같은 결과라 재시도가 의미 없다
- 급변은 원문 일부 누락이나 실제 대량 변동이다. 어느 쪽인지는 사람이 원문을 봐야 안다. 그대로 넘기면 대량 CLOSED·OPTION_REMOVED 오탐이 알림으로 나간다
- 실측 일 변동은 0~1개라 임계값을 넘는 일은 드물다

## 결과 · 트레이드오프

- 얻은 것: 같은 실패를 반복하지 않고, 오탐 이벤트가 쌓이기 전에 멈춘다
- 포기한 것: 실제 대량 변동이면 사람이 확인하고 수동 실행할 때까지 그날 diff·notify 가 늦어진다
