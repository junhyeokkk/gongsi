# 0006 운영 호스팅 — EC2 + RDS, 크레딧 관찰

- 상태: 제안
- 날짜: 2026-10-30
- 담당: 준혁

## 문제

금감원 API 는 날짜 파라미터가 없어 **그날 받지 못한 원문은 다시 받을 수 없다**. 로컬 PC 수동 실행으로는
매일 수집을 보장할 수 없으므로 상시 켜진 서버와 관리형 DB 가 필요하다.

제약
- AWS 신규 '프로젝트' 계정, 무료 플랜 — 크레딧 $100, 2027-04-30 까지. 크레딧이 끝나면 계정이 닫힐 수 있다
- 포트폴리오 목적 — 실무에서 흔한 구성과 운영 경험(배포 자동화·비밀값 관리·네트워크 분리)을 보여 주고 싶다
- 혼자 운영, 리뷰어 부재 — 손이 덜 가는 구성이어야 한다

## 선택지

1. **EC2 + RDS PostgreSQL** — 앱은 EC2, DB 는 프라이빗 서브넷의 RDS
2. EC2 한 대에 앱과 Postgres 를 같이 — 가장 싸지만 백업·장애 대응을 직접 해야 한다
3. Supabase(무료 DB) + 작은 서버 — 비용은 거의 0, AWS 운영 경험은 남지 않는다
4. ECS Fargate / Lambda + EventBridge — 하루 한 번 배치에 맞지만 구성이 커지고 비용 예측이 어렵다

## 결정

1번. EC2 t4g.micro 1대 + RDS db.t4g.micro(PostgreSQL 16, 단일 AZ, gp3 20GiB, 프라이빗 서브넷).
앱은 bootJar 를 systemd 로 상시 실행하고, 앱 안의 `@Scheduled`(Asia/Seoul) 가 매일 Job 을 띄운다.

## 근거

- RDS 는 자동 백업·스냅샷을 그냥 주므로 "다시 받을 수 없는 데이터"를 지키는 데 가장 손이 적게 든다
- EC2 + RDS + 보안그룹 + IAM 역할은 실무에서 가장 흔한 조합이라 포트폴리오 설명 가치가 크다
- 인바운드 포트 0: 배포는 GitHub OIDC → S3 → SSM Run Command, 접속은 Session Manager. SSH 키가 없다
- 비밀값은 SSM Parameter Store(표준, 무료) — Secrets Manager 월 과금을 피한다
- NAT 게이트웨이(월 $30+)를 쓰지 않으려고 EC2 는 퍼블릭 서브넷에 두고 퍼블릭 IPv4 비용을 받아들인다
- Docker 를 쓰지 않는다 — 1GB 메모리에서 데몬·레지스트리(ECR) 없이 jar 하나가 가장 단순하다

## 결과 · 트레이드오프

월 예상 비용 (서울, 온디맨드 정가 기준 추정 — **첫 주 Billing 실측으로 바꿔 적는다**)

| 항목 | 월 |
| --- | --- |
| RDS db.t4g.micro 단일 AZ | 약 $18 |
| RDS gp3 20GiB | 약 $3 |
| EC2 t4g.micro | 약 $8 |
| EC2 퍼블릭 IPv4 | 약 $4 |
| EBS 8GiB, S3, SSM | $1 미만 |
| **합계** | **약 $33** → 크레딧 $100 은 약 3개월(2027-01 말 전후) |

포기한 것
- 단일 AZ·단일 인스턴스 — AZ 장애 시 그날 수집이 빠질 수 있다. 15:00 재시도와 수동 실행 절차로 보완
- 크레딧이 개발 착수(2027-01) 즈음 바닥난다 — 아래 관찰 계획으로 판단 시점을 미리 정한다

### 크레딧 관찰 계획

- 매주 월요일 **Billing → 크레딧** 의 남은 금액과 **Cost Explorer** 일별 비용을 [survey/](../survey/) 에 한 줄 기록
- 예산 알림 `gongsi-monthly` $35 (런북 0단계)
- 판단 기준
  - 첫 2주 실측 일평균 × 남은 일수가 남은 크레딧을 넘으면 → RDS 를 Supabase 로 옮기는 ADR 을 쓴다(EC2 는 유지)
  - 남은 크레딧 **$20 이하** → 즉시 `pg_dump` 로컬 백업, 업그레이드(유료) 또는 Supabase 이전 중 하나를 결정
- 어떤 경우에도 크레딧이 끝나기 전에 전체 `pg_dump` 를 로컬과 다른 저장소 두 곳에 남긴다
