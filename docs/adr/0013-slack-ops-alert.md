# 0013 운영 알림 — 슬랙 Incoming Webhook, 발송 실패는 무시

- 상태: 제안
- 날짜: 2026-11-17
- 담당: 준혁

## 문제

혼자 운영하고 수집은 하루라도 빠지면 되돌릴 수 없다(ADR-0006). 실패·급변·재시도 마감처럼 사람이 움직여야 할 때 알아야 하고, 서버가 조용히 죽은 것도 알아채야 한다.

## 결정

슬랙 Incoming Webhook 으로 보낸다(`SlackCollectAlert`).

- 설정 `alert.slack.webhook-url: ${ALERT_SLACK_WEBHOOK_URL:}`, 값은 SSM `/gongsi/ALERT_SLACK_WEBHOOK_URL`(SecureString)
- URL 이 비면 로그만 남긴다
- 발송 실패는 warn 만 남기고 수집은 계속한다
- 알림: 매일 완료 요약(원문·상품·금리 변동·정규화 오류), 실패(단계·사유·다음 재시도 시각), 실패 뒤 복구, 급변 "원문 확인 필요", 오늘 자동 재시도 끝 "수동 실행 필요", 중단된 수집 정리
- 문구는 제목 한 줄 + 항목 목록(`CollectAlertMessages`)

## 근거

- 알림 때문에 수집이 멈추면 안 된다. 알림은 부가 기능이고 수집은 되돌릴 수 없다
- `{"text": ...}` POST 하나라 의존성이 없다. 비밀값은 웹훅 URL 하나이고 기존 SSM 경로를 그대로 쓴다(ADR-0006)
- 매일 오는 완료 요약이 heartbeat 역할을 한다. 안 오면 서버를 의심한다
- 요약 조회가 실패해도 완료 알림은 보낸다

## 결과 · 트레이드오프

- 얻은 것: 서버 상태를 슬랙 한 곳에서 본다. 웹훅 없이도 앱은 돈다
- 포기한 것: 발송 실패는 재전송하지 않는다. 슬랙 장애와 수집 실패가 겹치면 알림이 사라지고, 다음 날 요약이 안 오는 것으로만 알 수 있다
